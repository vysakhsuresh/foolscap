Nothing leaves your device. Here is how you can check.

Most PDF sites upload your file to a server, do the work there and send it back. Foolscap has no server. The work happens inside your browser, and the file never goes anywhere.

There is no server

This website is a folder of files: some pages, some scripts, some fonts. Nothing at this address can run code or receive a file. When you merge two PDFs, your browser does the merging, on your device, using scripts it already downloaded. There is nothing for it to send the file to.

The policy that enforces it

Every page is served with a Content-Security-Policy header. It is a rule your browser enforces: it says where the page may load things from and where it may send things. Ours is this, exactly:

default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; img-src 'self' blob: data:; font-src 'self'; connect-src 'self'; worker-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'; object-src 'none'

'self' means this website’s own address. connect-src 'self' means a page may only talk to this address — and because this address is a folder of files, nothing here can run code or receive a file. The policy also forbids inline scripts and anything from another domain, so no advert, tracker or third-party script can be added later without changing the header.

Check it yourself

  1. Open a tool page, such as Merge, and wait a second for it to load.
  2. Turn on airplane mode, or switch off Wi-Fi and mobile data.
  3. Add your PDFs and run the tool. It works, because nothing needs to be sent anywhere.

On a laptop, open the browser’s developer tools (press F12) and look at the Network tab while you use a tool. Every request goes to this site, and none of them carries your document.

One honest caveat

Showing some documents on screen can need a piece of the PDF renderer that is fetched from this site the first time it is used: a font the document did not embed, or a decoder for an unusual image type. That fetch goes to this site and carries nothing of yours. Once the offline service worker lands, those pieces will be stored up front and this caveat goes.

What we store

Your files, in your own browser’s private storage, on this device, until you leave the page. Each tool page clears that storage when it opens. Nothing is kept across visits, and nothing is sent.

We never put a file’s name, size, page count or contents into a log, an error message, a URL or a cookie. There are no cookies, and no analytics on tool pages.

Links that leave this site

Get help and Buy me a coffee are ordinary links. Nothing is fetched or sent until you tap one, and then it opens your mail app, WhatsApp or buymeacoffee.com, carrying nothing from this page. If you ask us for help, please don’t attach your documents: we never need them.

Still not sure? Good. Do not take our word for it: open the Network tab and watch.
